# 普通使用者怎样投稿

目前用 **GitHub Fork + PR** 提交，助手可以协助整理和操作；没有一键自动上传。
投稿只公开你本人有权分享、已经确认的脱敏方法摘要。安装或使用 Skill 不代表
同意投稿；其他人的项目资料不能由你代为授权。

## Skill 会怎样提醒

支持此机制的 Skill 应在发现**有证据且值得复用的成功经验**，或已经本人确认、
助手审核的原则时，主动提醒：展示精确拟公开摘要、适用边界、核验程度和投稿入口。
是否已有该提醒功能，以你实际安装的版本为准；本指南不表示你的 Skill 已经升级。

提醒不会自动公开内容。首次公开必须由你本人 opt-in；你可以逐条确认，也可以
给出范围明确、可撤回的持续授权，写清仓库、内容类别、适用限制和有效期。每次
仍须核对具体摘要在授权范围内；范围外或已撤回就不能上传。没有值得提交的新
内容时不应每回合提醒；你拒绝或要求暂停后，不应针对同一条目反复催促。

## 先让助手在本地准备

- **跑通的经验**：核对准确代码版本、该版本的相关真实运行、结果和适用范围。
  Git 改动或绿色徽章不能代替结果；代码测试不等于 Aspen 运行，更不等于工程验收。
  当前成功通道要求相关方法源码已公开；不能为满足条件擅自公开私人源码。
- **观点或原则**：先由你确认当前观点内容，再由助手审核同一内容的依据、冲突、
  边界和反例；内容变了，需要重新确认、审核。观点确认不证明技术结论成立。
- 助手展示最终拟公开摘要，确认你已授权这份内容，或它确实在有效持续授权范围内，
  再协助投稿；缺证据就写明待核。
  放宽标准的案例及其派生内容仍只留项目审计，不作为共享成功经验提交。

完整 `submission.json`、原始日志、模型、聊天原文、客户或个人资料、私人路径、
凭证、受限原件都留在本地。仓库目前**没有已配置的私人证据安全提交渠道**；
需要核验私人证据时，等维护者安排合适方式，不要把资料贴进公开 PR 或 Issue。
已经公开且有权引用的源码、具体 commit、运行结果可以附真实公开链接。

## 在 GitHub 提交候选

1. 打开[经验收件箱仓库](https://github.com/milklong888/chemical-engineering-experience-inbox)，
   使用 Fork 建立自己的副本。
2. 在副本中新增 `proposals/<条目ID>.md`，例如 `proposals/EXP-YYYYMMDD-公开署名-01.md`；
   先核对候选区和收件区，避免与已有条目 ID 重复。
   文件只放获准公开的候选摘要；不需要上传本地完整记录，也不要直接改 `inbox/`。
3. 向原仓库的默认分支创建 PR，说明这是待核候选。PR 一经公开，摘要已经发布，
   因此本人授权和脱敏检查必须在这一步之前完成。
4. 维护者独立检查版本、证据、授权与适用范围，满足准入条件后才将允许公开的
   摘要写入 `inbox/`。缺少核验时保持待核或退回，不能称为“已经收件”。

候选摘要写清：条目 ID、标题、类型、遇到的情形、采取的方法、观察结果或观点、
适用与不适用范围、已公开证据链接、仍待核实的事项，以及你选择的公开署名和
内容许可。只有本人已明确同意时，才声明该准确摘要可按 CC BY 4.0 分享；不附
私人授权原消息。字段合同与机读例子供助手在本地查阅 [准入协议](ADMISSION_PROTOCOL.md)。

CI 绿色只说明相应仓库检查通过；PR 提交或合并都不自动证明经验准入。临时箱中的
已收件条目也不会直接进入正式知识图谱或 Skill。后续由维护者发起单独的周期整理，
再走现有正式晋升流程。

## 可复制给助手的指令

> 请把本次工作中可能有用的方法经验整理为本地候选，按本仓库当前中文投稿指南
> 和准入协议核对。跑通类要核查准确代码版本、相关真实执行结果和作用范围；
> 观点类先把具体内容给我确认，再审核同一内容，改动后重新确认和审核。
> 请展示拟公开的脱敏摘要、适用边界、投稿入口和待核项；首次公开取得我本人
> 明确同意，之后也须确认每条内容及许可获得授权，或在我的有效持续授权范围内，
> 再协助用 GitHub Fork + PR 提交 `proposals/<条目ID>.md`。不要每回合提醒，
> 我拒绝或暂停后不要反复催促同一条目。
> 完整 submission.json、私人证据和受限资料留本地；缺少证据、权限或操作能力时
> 如实告诉我当前状态。只有维护者完成独立核验并收件后，才能说已经收件。

## 使用版本和撤回

主 Skill 仓库和临时箱分别更新。别人拉取的版本是否包含该流程，还要核对实际
版本及安装后的文件；某一台电脑已经更新，不等于所有人的 Skill 已同步升级。

尚未收件时可在 PR 中用条目 ID 和版本说明撤回；不要因此公开私人证据。
已经公开的内容可请求撤回记录或移除，但无法保证第三方克隆和历史副本消失。
完整许可与贡献边界见 [CONTRIBUTING.md](../CONTRIBUTING.md)。

GitHub 操作可参考官方的[创建 PR 说明](https://docs.github.com/en/pull-requests/how-tos/create-pull-requests/creating-a-pull-request)。
