# 化工经验临时收件箱

收集可公开、可追溯的方法经验，供维护者定期整理进 [chemical-engineering-skills](https://github.com/milklong888/chemical-engineering-skills) 和已有知识图谱。

这里的条目是**临时经验**，不直接成为工程事实、Skill 默认规则或默认检索知识。仓库不包含 Aspen 模型，也不自动采集任何用户的项目。

| 经验类型 | 进入临时箱的条件 |
| --- | --- |
| 实际跑通的经验 | 核实准确代码版本、相关执行结果、证据摘要、适用范围和来源链；核实投稿者公开授权及脱敏结果后直接收件 |
| 观点、宏观原则 | 用户确认当前条目内容后，由助手审核该版本的原则、边界和反例；审核通过再收件 |
| 缺证据、版本不符、未授权 | 保留本地待核，不以绿色标记或自报成功代替验证 |
| 使用放宽标准的案例及后代 | 仅保留项目审计，不进入本共享经验箱 |

Git 证明版本和改动。相关检查及其产物证明在该版本上做过什么。代码测试、无界面计算、Aspen 求解干净、原生对象执行、工程验收分别记录，不能互相替代。

普通使用者目前通过 **GitHub Fork + Pull Request（PR）** 投稿，没有一键自动上传或后台采集功能：

1. 让自己的助手在本地整理方法经验、核查证据，展示拟公开的准确摘要。公开须由本人 opt-in，可逐条确认，也可在明确范围的有效持续授权内进行；观点类还须本人先确认该观点，再由助手审核同一版本。
2. 在自己的 Fork 中新增 `proposals/<条目ID>.md`，只放经过授权和脱敏的候选摘要，再向本仓库提交 PR。完整 `submission.json` 和私人证据留本地。
3. 维护者独立核验后才收件，并维护 `inbox/`。PR 已提交、已合并或 CI 绿色均不能单独证明经验已准入。

详细步骤及可直接交给助手的指令见 [中文投稿指南](docs/USER_SUBMISSION_GUIDE.zh-CN.md)；许可与维护规则见 [投稿说明](CONTRIBUTING.md) 和 [准入协议](docs/ADMISSION_PROTOCOL.md)。公开摘要不附模型、原始日志、聊天记录、客户名称、私有路径、凭据或受限原件。

目前没有已配置的私人证据安全提交渠道。私人证据保留本地，由维护者另行安排核验；不要发进公开 PR 或 Issue。已经公开且有权引用的源码和执行证据可以附真实公开链接。

支持提醒机制的 Skill 应在发现有复用价值且证据充分的成功经验，或已经确认并审核的原则时，主动展示精确拟公开摘要、适用边界和投稿入口。首次公开须本人 opt-in；有效持续授权须范围明确且可撤回。提醒不等于上传，不应每回合提醒或在拒绝后反复催促。是否已有该机制，以实际安装版本为准，本指南不表示使用者已经升级。

维护者取得的独立验证记录保存在投稿仓库之外。提交者附带的“通过回执”不自动受信。`scripts/validate_experience.py` 是确定性准入检查器；它不会联网、运行投稿中的命令、上传内容或修改正式知识库。

[`examples/`](examples/) 和测试用例是合成示例，供本地理解合同，不能作为真实工程经验入库；不要把填好的完整记录直接公开。`proposals/` 用于投稿候选，`inbox/` 由维护者写入通过当前准入流程的公开摘要。出现反例时保留版本历史并撤回相关适用声明；内容有变化，需要重新绑定确认与审核。

用户明确发起周期整理后，再按现有中央规则执行去重、来源复核、反例与留出验证、唯一归属审查、正式晋升和回退记录。收件数量不是学习质量指标。

验证器代码采用 MIT 许可；投稿内容按每条明确声明的 CC BY 4.0 许可分享。每位投稿者须有权公开相关内容；他人的使用行为不构成授权。

主 Skill 仓库与本收件箱分别发布。其他使用者是否已有收件流程，以其实际拉取的版本和安装后的 Skill 内容为准；本机更新不会自动升级所有人的安装，也不会替任何人授权投稿。
