# 双效harness：具体禁止什么，何时适用，如何发现

harness在本卡专指任务约束与不应执行的动作，不假装已经实现自动拦截程序。对话中明确的工作要求与独立来源支持的结构检查分别标明；没有引用私人模型的运行结论或修复轨迹。

## A. 来自明确任务要求的工作护栏

| ID/触发 | 不要做 | 应做/检查 |
|---|---|---|
| DE-U01 仅规划、取证或连接审查 | 不擅启新流程、改工况或把只读查连接扩成重建 | 按授权阶段停止；已有模型优先只读COM/原生导出 |
| DE-U02 已有稳定基线，只增换热器 | 不为换热器擅改受保护进料、产品、塔工况和原岛边界 | 先列允许改动及当前边界，超出范围不默默调参；有据trim另列 |
| DE-U03 用户要求实体换热模块 | 不只连热流、复制一股流或放空HeatX占位就称完成 | 逐口说明真实冷热两侧的来源、去向和热职责 |
| DE-U04 比对权威模块 | 不凭示意相似或“等价”一词跳过差异核对 | 逐项列物料路径、热职责、返回、产品和抽象层级；不同处说明条件 |
| DE-U05 循环接回 | 不在返回未调和时硬接母流程，不以改目标掩盖尺度漂移 | 先核净采出/gross循环和返回状态，再按原接口接回 |
| DE-U06 清旧流股 | 不只删图面、按名字清零或忽略旧控制引用；不误删合法产品/排气终端 | 查实际端口及TEAR、DS、Calculator等引用，确定残留才清理 |
| DE-U07 查整块及完整流程 | 不只看共享HeatX或一个塔、就称全流闭合 | 核HP回流、LP返汽、净采出、跨塔及母流程接口；终端必须有职责 |
| DE-U08 界面受阻 | 不把锁屏当所有COM/文件核对停止的理由，不以开窗口替代连接证据 | 继续已授权且独立可做的后台工作；图面未做明确保留 |
| DE-U09 验收范围 | 不把读不到的Summary写0，不把清洁消息等同完整计数表 | 分项列已核/失败/未知；当前合同未满足的门保持未满足 |
| DE-U10 交付与交接 | 不以记录“应该发送”代替已授权的实际发送；不将已发送说成接收方完成 | 记录实际回执；文件、图、求解、接收任务分别报告 |
| DE-U11 经验维护阶段 | 不把改进卡直接装Skill、写默认RAG或建活动数据库 | 只进experience候选区；后续正式采用另走维护者流程 |
| DE-U12 范围限制更新 | 当前排除EDR或其他细化时不擅自添加，也不把早期限制当永远有效 | 以最新授权为准记录变化；无严格最优要求时不自行扩大成全局寻优任务 |

## B. 不同构型各自的结构harness（专业审查候选）

| ID/构型 | 不要做 | 检查对象与允许例外 |
|---|---|---|
| DE-S01 平行进料 | 不擅自等分原料；不在用户要求全料进一塔时重加分流 | 来源分料授权、各塔产品义务、混合前结果；并流只是候选 |
| DE-S02 串联进料 | 不从顺流/逆流名称猜顶/底跨塔，也不把第一塔当高压塔 | 每股实际跨塔物流与方向、净/gross、压力路径 |
| DE-S03 热流抽象 | 不宣称已经有四物料口HeatX、面积或实体循环 | 核真实端器热服务；可保留合法内部端器和公用工程侧Heater |
| DE-S04 显式HP冷凝 | 不拿净馏出物当gross顶蒸汽；不丢回流；不重复同一过程相变职责 | 热侧进出、回流/净采出、全/部分冷凝和非凝气；公用工程抽象不是重复职责 |
| DE-S05 显式LP釜式近似 | 不丢返汽或液体净出口，不同时内外重复取底产品 | 汽液分离职责、返塔阶段、底产品总账；FLASH2只是有条件近似 |
| DE-S06 热虹吸/强制循环 | 不强制所有出口先FLASH2；不由两相出口宣称自然循环已成立 | 两相返塔/集液区、净采出、液柱及压降；循环泵取决于真实型式 |
| DE-S07 部分热集成 | 不强迫Q全部相等或把回收热重复算节能；不把trim当主回收 | 热源/受热/残余公用工程唯一职责，逐项能量账 |
| DE-S08 所有构型的HeatX出口 | 不把所有离开岛的流当漏接；不把未知出口随意命名为产品 | 返回、产品、排污和跨工段终端分类；每类有来源和后续职责 |
| DE-S09 所有构型的热压 | 不从高低压标签或两个端点温差直接判换热成立；不让低压流无压头返高压 | 物性、整段温焓、各侧压降与兼容加压/降压路径 |
| DE-S10 所有构型的控制 | 不让DS与Calculator抢写同一量，不改既有求解容差换收敛 | 合法独立Vary、内外层顺序、同产品比较及精度前后证据 |

本节是按独立公开来源整理的待核审查方式，不是声称已有某模型出现过这些技术错误。[结构改进卡的来源](EXP-20261020-double-effect-structure.md)支持构型差异及实现边界，具体端口/型式仍需同版本验证。
